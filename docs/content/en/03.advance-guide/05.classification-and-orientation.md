Mobile camera captures and document scans often feature skewed angles, upside-down documents, or mixed text directions.

RustO! provides two distinct orientation correction stages:

```mermaid
flowchart TD
    A["Raw Input Image<br/>(Sideways / Skewed Document)"] --> B{"1. Whole-Page Orient?<br/>(orient.rten)"}
    B -->|Enabled| C["Classify & Rotate Page<br/>(0&deg;, 90&deg;, 180&deg;, 270&deg;)"]
    B -->|Disabled| D["2. DBNet Text Detection<br/>(Extracts Text Polygon Quads)"]
    C --> D
    D --> E{"3. Text Line Direction CLS?<br/>(cls.rten)"}
    E -->|Enabled| F["Inspect Crop & Rotate Inverted Lines 180&deg;"]
    E -->|Disabled| G["4. CTC Text Recognition<br/>(rec.rten + dict.txt)"]
    F --> G
```

---

## 1. Text Line Direction Classifier (CLS)

The CLS model inspects cropped text regions produced by the DBNet detector. If a text line is inverted (180° upside-down), it rotates the crop upright before passing it to the CTC text recognizer.

> [!NOTE]
> Text line direction classification (`cls.rten`) is supported on **PP-OCRv4** and **PP-OCRv5** models. PP-OCRv6 models use an orientation-robust recognition network.

### Initialization Configuration

```rust
use rusto::InitializeConfig;

// Initialize engine and attach CLS model with 0.9 confidence threshold
let config = InitializeConfig::ppv5("models/det.rten", "models/rec.rten", "models/dict.txt")
    .with_cls_threshold("models/cls.rten", 0.9);

let mut ocr = RustO::initialize(config)?;
```

### Request-Local Activation

Enable CLS classification for specific scans via `OcrRunOptions`:

```rust
let options = OcrRunOptions {
    classification: Some(true), // Activates CLS evaluation for this request
    ..Default::default()
};
```

## 2. Whole-Page Document Orientation Classifier

For documents photographed sideways (90° / 270°) or completely upside down (180°):

```rust
let config = InitializeConfig::ppv5("models/det.rten", "models/rec.rten", "models/dict.txt")
    .with_orientation_threshold("models/orient.rten", 0.85);

let mut ocr = RustO::initialize(config)?;
```

### RapidAI v2 page model (0.4.0)

The RapidAI v2 page orientation model needs different pre-processing from the line classifier: resize the short side to 256, centre crop 224, ImageNet normalisation. Use the preset instead of a hand-built config:

```rust
use rusto::OrientConfig;

let orient = OrientConfig::rapid_orientation_v2("models/DocOCR/orient_rapidai_v2.rten");
```

The default `OrientConfig` keeps the old stretch pre-processing (used by the line CLS model). The model is downloaded by `scripts/download_doc_models.sh`. Inside `DocPipeline` the correction is applied only when the confidence is at least 0.6; the result reports `applied_degrees` (clockwise rotation applied to the scan) and `detected_degrees`. See [Document Layout, Tables & Orientation](/en/advance-guide/document-layout-and-tables) for the coordinate contract, `rotate_box_back` and why callers must check `stages`.

### Request-Local Activation

```rust
let options = OcrRunOptions {
    orientation: Some(true), // Classifies and rotates the whole page before detection
    ..Default::default()
};
```

## 📱 Cross-Binding Example (React Native)

```typescript
import { detectText, initialize } from '@rustors/react-native';

// Initialize with model references
await initialize({
  preset: 'ppv5',
  models: {
    detection: 'det.rten',
    recognition: 'rec.rten',
    dictionary: 'dict.txt',
    classification: 'cls.rten',
    orientation: 'orient.rten',
  },
});

// Enable orientation correction on demand
const results = await detectText(
  { uri: 'file:///path/to/sideways_document.jpg' },
  {
    orientation: true, // Fixes 90°/270° whole-page rotation
    classification: true, // Fixes 180° upside-down text lines
  }
);
```
